## Wrapper and unchanged scientific decision

At native fixture lines391–400, the new wrapper imports only the explicitly
declared tests-package helper and forwards the current module, returned record,
publication receipt and existing fixture values. It does not itself read files,
call the workflow, construct geometry or alter the result.

The case retains exactly one _execute_workflow call using STEP/PLY bytes and
fixed policies. Truth remains outside that invocation. Original CASE_RESULT
publication and aggregate-size admission precede the supplemental call. The
same preconditions—full returned workflow, source consistency and no execution
error—guard both integrity and accuracy evaluation.

In the reviewed current source, an ordinary helper exception is captured only
in diagnostic_error, then an independent try invokes original _evaluate. Helper
success/failure does not directly set positive, oracle_error or original status.
However, both calls receive mutable shared objects: a helper that changes the
record/raw/triangles could influence the later original evaluator even when its
post-hash detects mutation and marks integrity failed. Catching the helper's
exception does not restore the original values. An original PASS influenced by
that mutation would no longer be an unchanged scientific observation.

Root's proposed correction is therefore accepted: invoke unchanged _evaluate
first, retaining its original try/except/positive handling, then independently
invoke the supplemental ledger regardless of the ordinary accuracy outcome.
Keep the original preconditions and durable-result ordering. The supplemental
need arises because the serial oracle may stop early, not because the ledger
must precede it; a caught accuracy error still allows the complete ledger to run.
No deep copy, second decode, file reread, inference or changed assertion is needed.

The ledger must still bind the supplied record to the original publication hash
before and after its predicates, and protect/check raw/triangle immutability.
Any unexpected mutation by the original oracle would fail the ledger's initial
publication binding rather than being normalized into a new original value.
Global interruption, process termination, KeyboardInterrupt/SystemExit or
exhausted budget can prevent later work; those outcomes remain incomplete.
Do not swallow them to claim that either evaluator always completed.

This prospective correction supersedes the accepted design's call-order
recommendation only. It preserves its eight groups, truth isolation, original
oracle, one inference, original durable result, all bounds and four-file layout.
The corrected wrapper source must still be read before the exact PRE.

The unchanged current _evaluate still requires nonempty measured groups, every
original scan-derived radius/sweep oracle, raw-frame/uncertainty/nominal-deviation
semantics, nonempty predictions and every generator/axis endpoint localization
oracle. The first accuracy failure can still leave later assertions UNREACHED.
The supplemental ledger must not infer their success.

Current AST inspection found 20 original test functions, 39 prospective outcomes
(38 pure/mock and one native). The new _mock_recorder stub is explicitly
MOCK_LEDGER_NOT_NATIVE_INTEGRITY_EVIDENCE; it preserves the existing invented
recorder tests without claiming that their tiny reports qualify native integrity.

## Separation and remaining helper-dependent obligations

The wrapper intentionally does not make original status depend on the ledger.
Consequently an original native PASS or harness exit zero is not sufficient for
diagnostic admission. Conversely, original native FAIL/exit one can coexist with
complete integrity, but only exact independent POST may classify that result.
Every supplemental test must pass and every applicable integrity criterion must
be complete; a generic nonzero pytest exit is not a permissible diagnostic.

Before final PRE, require focused checks of the actual integration, in addition
to helper unit tests:

- A durable original RESULT exists before the supplemental call, and no fifth
  scientific file is created or the original result appended.
- Original accuracy executes before the supplemental call. An ordinary original
  accuracy exception still reaches the supplemental ledger, and its result
  cannot change the already recorded positive/oracle_error decision.
- Ordinary supplemental exceptions remain separate diagnostic_error values;
  they never erase or replace the original accuracy result.
- Failed, missing or oversized ledger evidence cannot qualify diagnostic
  admission even if original accuracy passes.
- Record, raw rows and triangles remain unchanged through the supplemental
  call; detected mutation fails integrity. The corrected ordering additionally
  prevents helper mutation from affecting the original accuracy computation.
- Truth is unused inside the helper; no fixture, inference, sampling, native
  geometry or fit call is introduced.
- Completed UNAVAILABLE/no-cover and valid early refusal are distinct. Common
  predicates must not spoof PARTIAL to satisfy the legacy positive binder.

Passing truth through the compatibility signature does not itself establish
truth isolation; the helper source and tests must do that. Similarly the wrapper
does not enforce 32 KiB or supplementary time/work limits itself: the completed
helper plus envelope checks and final global supervision must establish them.
The agreed design's report-binding versus native-array-recomputation limitation
remains in force.
