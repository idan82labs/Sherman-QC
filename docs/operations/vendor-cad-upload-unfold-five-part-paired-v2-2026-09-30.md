## End-to-end arms and safety envelope

`scripts/evaluate_vendor_cad_upload_unfold_v2.py` runs the unchanged maintained
upload route body in an isolated catalog; no live legacy module import, HTTP
auth claim or live database. Native STEP upload V1 produces source-bound bend
records and folded PLY for the control. Challenger native upload V2 uses the
same six-decimal degree representation already published by the extractor at
the existing lower 15-degree eligibility boundary (raw upper cutoff unchanged),
preserving unrounded native sweep records. This is a numerical representation
policy, not a manufacturing tolerance. Each claimed case executes control V4 transport3 then
challenger V5 transport4 through the maintained vendor GET body. Distinct local
catalogs and candidate UUIDs are retained; UUIDs are not inference features.
The same raw bytes, source order, candidate extraction and whole-case budget
apply to both arms; candidate policies are separately declared, not silently
assumed identical. No former attempt is reopened or rescored.

Limits before execution: 60 seconds and 4 GiB process-tree RSS per WHOLE case
(both uploads, both flat workers and oracle included), 330 seconds whole
campaign including 30-second preparation/cleanup allowance, five serial cases,
5,000,000 source bytes, 40,000,000 result bytes per artifact and 1,000,000 bytes
per log. No started limit is modified. One heavy native job at a time; shared
cross-profile slot, OS lock and durable PGID admission/quarantine remain active.
Parent observes child return codes and confirms group quiescence before release.
Failed cleanup halts/quarantines; failures, crashes, abstentions and not-run
cases remain in the five-case denominator. Native oracle refusal empties the
published flat preview; no automatic fallback or fabricated result.

## Freeze, independent PRE, single execute, independent POST

Freeze is exclusive and source-only. It records every declared source payload,
member hash, interpreter/native runtime pins, protocol, routes, case bindings,
budgets, failure handling and decision rules before any physical execute.
Independent non-author PRE must verify all hashes/archive members, exact five
raw bindings, isolated route dispatch, complete source closure, source-only
tests, admission quiescence and budgets. Only GREEN permits one execute.

Independent POST checks unchanged source/raw/candidate provenance, all ten arm
outcomes, observed exits/RSS/timing, output hashes, admission cleanup and the
complete native oracle ledger. Only released retained outputs may feed browser
QA. Derived screenshot/selection artifacts remain separately versioned.

Acceptance: preserve incumbent's two available cases; recover at least one
previously refused case via a generic mechanism; every challenger AVAILABLE
must pass the complete discrete native metric oracle and full transport4
contract. An honest negative result is retained and motivates a new successor,
not a changed scoring rule or retry. Report availability on all five, not F1 or
bend-count accuracy (there is no independent manufacturing bend-count truth).

Visual gate: maintained app, desktop and tablet, folded/flat toggle, top/bottom
and four oblique views, every bend overlay selection and grouped selections.
Inspect representative images for visible bend/flange marking, holes, flipped
or collapsed triangles; retain page/request errors and refusals. Controlled
local integration only after independent geometry/transport audit; public Site
publishing and manufacturing release are outside this run.
