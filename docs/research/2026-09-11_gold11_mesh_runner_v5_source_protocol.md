## Resources and supervisor boundary

One worker, serial:

| Resource | Fixed prospective limit |

The parent clock starts before source preflight and attempt creation. Source
reads, launch, worker monitoring, cleanup, source postflight, publication and
final three-file checks consume this same180s interval. A slow preflight reduces
the remaining worker opportunity; no timer is reset to supply another175s.
The worker's120s CPU limit includes its source preflight/import/tests and does
not grant a parent CPU cap. Thread-count environment settings are1.

The copied V4 polling/reaping mechanism uses `/bin/ps`, at most2s or the remaining
deadline per sample, and short selector waits. The separately named function
and receipt use this gate's literal120/175/180 values; no45s field is overwritten
on an old supervisor object. New localized ledger safeguards charge observed
log bytes before writes, retain write-count uncertainty, report unsampled RSS
as unknown rather than zero, and close selectors/streams only after attempting
owned-child cleanup. Ordinary close errors veto rather than hide custody.

RSS is sampled, not an allocation sandbox. During work the gate checks owned
group RSS plus the parent's high-water value against2GiB. At termination it
also requires reaped-child high-water plus parent high-water within2GiB; this
sum is deliberately conservative, not a measured simultaneous process-tree
peak. Worker self high-water is separately checked. Darwin byte units are an
explicit runtime premise. Unknown/failed custody cannot be promoted by a low
sampled value.

Popen, pipe/log/file I/O, fsync and some OS operations are synchronous. The
limits are monitored deadlines and bounded waits, **not hard real-time parent
termination** or protection against uninterruptible OS calls. The overall
return also checks the deadline after final publication and stdout. A pending
COMPLETED status is not release evidence if the observed parent exit is nonzero,
final inventory/clock checks fail or independent POST is absent.

Only the new worker's owned process group is signaled. Unexpected same-group
children cause failure; known survivors may be killed and resampled within the
remaining reserve. An unfamiliar surviving PID is retained as unconfirmed,
not signaled on an identity guess. This mechanism does not discover escaped
groups or attest all descendants against malicious process regrouping. The
reviewed tests create no actual subprocesses; process/timer/raw-reader seams
are explicit mocks. This source gate is not an OS security/sandbox qualification.
