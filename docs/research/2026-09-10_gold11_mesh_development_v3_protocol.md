## One-use dispatch and all-22 scoring barrier

Independent `PRE_RUN_AUDIT.json` must state
`GREEN_FOR_FROZEN_CONSUMED_DEVELOPMENT_RUN`, the exact canonical bundle SHA, an
identified reviewer and no blocking findings. The technical audit is not human
manufacturing approval. The parent rejects preexisting start, terminal, veto,
dispatch, score, case, leaf or coordinator-work state using `lstat`; a dangling
marker is spent state, not absence. Exclusive publication is never overwritten.

`STARTED.json` consumes this attempt. Failed post-publication finalization leaves
a veto where possible; no worker/case/arm-only resume interface exists. The outer
parent issues one neutral capability to a verified coordinator in a dedicated
process group. The coordinator issues one-use leaf capabilities bound to parent,
role, arm, geometry/request hashes, source/runtime/control hashes and the exact
owned private cache inode. Claim publication spends a capability before leaf
source/runtime/input access. Arbitrary caller-selected cache/source/pose APIs are
not admitted. Workers receive neutral cached `scan.ply` and `cad.step` bytes,
not original paths, case/family labels, references or reference-derived poses.

Inference leaves run serially: eleven cases times two arms. A case may be
terminally unavailable before native dispatch; 22 outcomes do not mean 22
successful executions. Both success and refusal produce whole scoring projections
and terminal receipts. No timeout/malformed/native/work failure is dropped from
the denominator. An abort fills missing terminal records without running work
again. Failure to durably retain derived result bytes vetoes campaign scoring;
it is not converted into an apparently complete diagnostic.

Only after all 22 inference records are durable and terminal may the coordinator
publish `INFERENCE_TERMINAL.json` and open the fixed catalog. The barrier binds
strict integer counts 11/2/22, all scoring outcomes and selected result hashes.
The separate scorer validates its parent/role/capability and this barrier. Gold
never reaches inference or candidate selection. If scoring or final custody is
unavailable, report a terminal incomplete score, not fabricated TP/FP/FN totals.

The Python audit hook blocks reviewed accidental filesystem/network/process
operations outside the frozen source/runtime/private-cache scope. It is not an
OS sandbox against hostile native syscalls, a malicious local writer, PID reuse,
or replacement of the executable. These limitations remain part of the result.

## Budgets, timers and process custody

Only one heavy/native geometry worker at a time. Numeric libraries use the
shared supervisor's one-thread environment. MiB/GiB below mean binary units.

| Phase/resource | Frozen limit and enforcement scope |
| --- | --- |
| Execution source/control preflight | 20 s parent alarm, preceding the 4,200 s campaign clock; source-only |
| Campaign | 4,200 s monitored parent campaign, including a 30 s terminalization reserve; coordinator dispatch/cache setup/supervision use the remaining work deadline, initially approximately 4,170 s |
| Inference leaf | 180 s case allowance minus preparation elapsed for supervision, local alarm around synchronous supervisor work; worker RLIMIT_CPU 150 s; sampled leaf-tree RSS 8 GiB; output log 1 MiB |
| Coordinator | Current/own high-water RSS 4 GiB; outer sampled owned-group/descendant plus outer-parent RSS 12 GiB; coordinator log 2 MiB |
| Scorer leaf | Local 60 s alarm around supervision including synchronous helper/Popen/stdin/log work; worker RLIMIT_CPU 50 s; sampled leaf-tree RSS 2 GiB; output log 1 MiB |
| Parent IO regions | 20 s for named bounded reads/preparation/result retention; final phases also limited by remaining campaign allowance |
| Input/result transport | Scan 64 MiB, CAD 8 MiB; full result 128 MiB per arm-case; scoring projection 8 MiB per case; scorer request 192 MiB, original/enriched scorer result each 32 MiB |
| Dispatch/control bounds | Leaf request/dispatch 16 KiB; coordinator stdin request 4 KiB; source/FROZEN/pre-run audit/parent final records use their fixed source-declared bounds |

This is not a hard 180 s whole-case or 60 s whole-scoring finalization guarantee.
Input/cache preparation, dispatch, result retention, temporary-cache cleanup and
terminal publication have their stated separate regions or global supervision.
Successful case processing checks elapsed time after retained-result decoding and
vetoes if it exceeded 180 s. Failure receipts may exceed that duration. Scorer
request preparation/dispatch precede its local supervision timer; result retention
uses its existing 20 s finally region. No limit has been enlarged to hide this.

The helper may catch a local timeout, kill/reap and confirm owned processes during
up to five additional failed-cleanup seconds; that time is reported and remains
subject to the caller's outer budget/reserve. Nested alarms use the earlier live
timer and restore its remaining duration. They are catchable Python signals,
not an independent hard-kill watchdog. Blocking/uninterruptible OS operations,
temporary-directory cleanup, already-fired one-shot alarms or final publication
can prevent a guaranteed exact parent termination time. The optional final veto
write is bounded to one additional second. A wall overrun or lost terminal proof
remains a failure; it cannot become a successful run by descriptive wording.

The outer coordinator owns one PGID. Samples include that group after leader
exit, rooted descendants and retained observed identities without duplicate RSS.
Success requires direct-child reaping and observed owned-group emptiness. Inner
leaves share the coordinator PGID; cleanup may signal only the direct/known
same-identity leaf descendants, never the whole shared group. Detected foreign
escape or any known PID changing PGID creates a permanent custody veto. Unknown
identities remain explicit and conservatively accounted, never permission to
signal their new group. Owned-group emptiness does not claim an observed foreign
escape was removed. Unobserved native fork/reparent races remain a limitation.

RSS is sampled, not an OS allocation cap. A child exiting before any sample has
an explicitly unknown tree peak, not a measured zero. Worker own high-water
logs and available process receipts must be reported separately; no missing peak
is invented and no single sample certifies all descendants' peak allocation.
Malformed/missing monitor evidence, uncertain cleanup, selector/stdout close
errors or a nonzero/signal exit veto clean supervision.
