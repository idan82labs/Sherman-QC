## Transport capacity: reviewed pre-freeze correction

The unchanged engine admits a complete V13 workflow of up to 128 MiB, measured
by streaming compact JSON with default ASCII escaping. The initial native draft
wrapped it inside a 32 MiB `CASE_RESULT.json`, which could whole-discard a valid
engine publication solely by transport. This was a source-derived possibility,
not a demonstrated size of the L-R result or a result of a native attempt.

Root's unexecuted correction uses a **129 MiB case-result cap** with a separate
**1 MiB recorder envelope check**. Let `E` be the compact encoding of a shallow
record copy with `workflow=None`, and `W`
the compact workflow encoding. For this ordinary fixed-schema JSON tree,
sorting dictionary keys changes order but not encoded length. Replacing the
four-byte literal `null` gives

`bytes(CASE_RESULT) = bytes(E) - 4 + bytes(W)`.

The source explicitly requires `bytes(E) <= 1 MiB`, while the unchanged engine
guarantees `bytes(W) <= 128 MiB` for its detailed publication. Together these
yield at most `129 MiB - 4 B`. The independent final 129 MiB encoding cap and
existing whole-refusal path remain. Small engine publication-refusal envelopes
also fit this allowance; they do not become positive measurements. `_check_result_metadata`
runs before the full wrapper write, uses `dict(record, workflow=None)`, and
neither traverses nor changes the returned workflow. It does not copy/refit
raw geometry or discard any field from the actual retained full record.

Two new mock tests are discriminative. The first uses an unencodable ordinary
object as workflow, builds an ASCII metadata string to the exact 1 MiB edge,
then requires refusal at one additional byte. The second lowers only the
mock metadata ceiling and requires the whole-refusal receipt, absent workflow,
false full-retention flag, zero oracle calls and no partial publication file.
These are source-reviewed assertions, not reported passes.

The corresponding four-file aggregate is **138 MiB + 4096 B = 144,707,584 B**:
129 MiB result, 8 MiB CAD, 1 MiB scan and 4096 B start. Fixture cap,
supervisor inventory/aggregate cap, source assertion and protocol now agree;
all four filenames and original oracles remain. No engine work cap,
connected registration transport cap or physical policy is changed by this
correction. The explicit null-workflow-envelope check makes this more than an
assumed metadata allowance.

The envelope is recorder metadata, **not oracle-result storage**: the oracle
runs after durable `CASE_RESULT.json` and its summary is printed into the
separately limited OUTPUT receipt. Keep the 1 MiB stdout ceiling and terminal
negative handling for output overflow. `_encode` retains fragments then joins
them; envelope/transport byte limits do not bound Python object overhead,
transient allocations, total RSS or native runtime. The 4 GiB sampled group
ceiling remains necessary and is not a continuous peak-RSS guarantee.
