## Unscored boundary

There is no catalog/reference global in the extracted namespace, no reference
selector, no scorer worker/dispatch/arguments, no all11 scorer entrypoint, and
no --score mode. The only child modes are inference --worker and the new
--internal-coordinator. Leaf role validation rejects SCORER before control reads.
The publication policy rejects scorer request/result/report/reference artifact
names. NO_SCORE_POLICY is bound into the frozen profile, PRE, coordinator
context and terminal publications. all11_release_allowed remains False even on
successful diagnostic custody.

The existing filename SCORING_INPUT.json and V2 contact-wrapper transport are
retained because they are the reviewed exact-result/projection seam. This is a
transport name, not authority to score. Reconstructing the inner contact payload
does not invoke any scorer. Its canonical hash is diagnostic provenance only.

Actual V2 projection loads the unchanged, qualified pure dependency graph, which
contains scorer function definitions and NumPy/SciPy imports. The projection
loader already uses that graph without invoking matching/scoring; the new
diagnostic cannot honestly remove those dependencies and still claim the same
qualified projection. No scoring function is extracted into the orchestration
profile or called. No reference bytes are supplied to the graph. This dependency
distinction is explicit rather than disguised as a new numerical projection.

## One-use controls and private custody

Freeze reads only the declared source files and runtime version metadata, parses
the fixed CASES source and publishes a new exclusive source snapshot/FROZEN.
It does not stat or open physical inputs. The new exact PRE must bind the frozen
bundle, profile hash, case order, six-slot denominator, limits, no-score policy,
reviewer and zero blocking findings. No V5/V6 PRE is accepted as the diagnostic
PRE and no command-line option supplies missing authority.

Before STARTED, verification rebinds current/frozen source bytes, runtime metadata,
the fixed CASES declaration and the whole profile. A named source-tree shape
check rejects undeclared/missing source names before dispatch without reading
unknown contents. The attempt root must contain exactly source, FROZEN.json and
PRE_RUN_AUDIT.json. Any STARTED, terminal marker, partial publication, old cache
or other name makes the attempt spent/invalid; there is no resume flag or cleanup
to make it reusable. Failed STARTED publication gets a best-effort no-dispatch,
six-slot administrative veto, not a newly retryable state.

The coordinator cache is a new private /private/tmp directory, outside the
retained attempt. Path/device/inode/uid are bound before dispatch; cwd/HOME/TMPDIR
and identity are rechecked before activation. The cache remains opaque outside
RUN on success or failure. No contents are enumerated, inventoried or reclaimed.
Neutral coordinator context includes the new leaf schema, diagnostic profile
hash and no-score policy; issued/claimed inference records bind its digest and
the fixed arm/input hashes without source paths or Gold.

The unchanged V6 owned_leaf_cache/retain_worker_result/supervise_case paths use
an explicitly declared new cache-prefix factory. They do not automatically
delete via TemporaryDirectory. Receipt quiescence and original fresh identity
precede any private result enumeration/read. Cleanup follows successful derived
retention, or proven no dispatch, and applies only to the exact new directory.
Unknown writer custody or failed derived retention leaves that cache opaque.
Identity/cleanup failure is explicit, potentially partial, and aborts subsequent
dispatch. No outer fallback discovers or reclaims leaf private directories.

Source-input hash failure also stops subsequent dispatch. All six slots still
exist, but later slots can only be explicit terminal unknown/refusal records.
There is no scoring after an abort because there is no scoring path at all.

## Terminal evidence and unknown-name veto

The coordinator retains/reconstructs each usable original RESULT through the
actual V2 wrapper and exact full arm request. For an unavailable/killed/failed
worker, it preserves the exact supervisor refusal and any already retained
complete/partial artifact bytes, without parsing a partial as successful
inference. Clean results additionally require source binding, V3 quiescence,
successful derived retention and completed private-cache cleanup.

INFERENCE_TERMINAL binds the six-slot evidence digest, profile, arm requests and
no-score policy. It does not claim all22. The outer process independently
reconstructs all six slots only after whole-group quiescence and checks that
digest plus the coordinator's explicit unscored completion. Successful original
results require issued and claimed neutral dispatch records. Negative slots are
not removed to obtain a favorable denominator.

Each row retains source/arm/result/projection/receipt hashes, typed exit/budget
and custody state, returned workflow diagnostics, and the original receipt/log
locations. CPU/HWM/current-RSS scopes stay those of their original receipt/log;
the row does not fabricate a combined resource number or infer a killed stage.

Closed logs are hash/count checked after quiescence with the inherited semantics:
the digest binds the observed retained file, not bytes cryptographically hashed
by the supervisor at capture time. Unknown observed-byte counts on a failed
attempt remain unknown. This limitation is stated in the log evidence and cannot
be promoted into stronger custody by a source-only gate.

Outer content source/control postflight, terminal fill, retained-result reads and
inventory are all behind strict V3 whole-group quiescence. Source postflight
failure remains failure while six-slot terminal materialization is attempted
within remaining time. No such content work runs with unknown writers.
DIAGNOSTIC_EVIDENCE is a bounded 256 KiB derived receipt; a larger complete ledger
fails whole rather than silently dropping rows or stage fields.

The new campaign schema admits only declared source/control/inference/result/log
and six inference issued/claimed namespaces. It has no coordinator_work,
private-cache or scorer/reference branch. The unchanged V6 inventory algorithm
charges every unknown name to the unchanged scientific128 bound, inspects only
unknown metadata and never recurses or reads unknown content. It rescans the
entire admitted tree after COMPLETED and again after FINAL_GATE. Drift, unknown
names, byte-count/hash failure, envelope overrun or terminal publication failure
veto success. The 256 KiB envelope is a checked bound, not a promise that maximal
adversarial receipts fit.
